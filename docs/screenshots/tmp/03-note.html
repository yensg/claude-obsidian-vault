prompt-caching

Prompt caching cuts token cost by up to 90% by reusing stable prompt prefixes — the most impactful single optimisation for high-frequency Claude API calls.

1️⃣ What is this really?

Claude's API caches a prefix of your prompt so repeated calls reuse the cached tokens rather than reprocessing them. The cached prefix must be at least 1,024 tokens and is marked with cache_control: {type: "ephemeral"}. Cache TTL is 5 minutes. (extracted)

2️⃣ Concrete example (from my work)

The /vault skill has a large system prompt (the full SKILL.md instructions). On every invocation, that prefix is stable — only the user's conversation changes. With caching: the first call computes the prefix, subsequent calls within 5 min pay only output tokens on the cached segment. Result: ~80% cost reduction on long sessions. (inferred — applied from Anthropic's published cache hit rate)

4️⃣ Compare / contrast

ApproachCost modelWhen to use
No cachingFull input tokens every callShort, one-off prompts
Prompt cachingWrite once, read cheap (5 min TTL)Repeated calls with stable prefix
Batch API50% discount, asyncNon-real-time bulk processing

5️⃣ Anti-patterns (what NOT to do)

  • Don't cache dynamic content (timestamps, user IDs) — defeats the purpose; every call is a cache miss.
  • Don't forget the 5-minute TTL — long gaps between calls evict the cache silently; budget accordingly.
  • Don't put cache_control mid-prefix — only the last marked breakpoint is cached; earlier marks are ignored. (extracted)
